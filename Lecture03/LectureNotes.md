# Terraform Lecture 03  
## Types and Values – Terraform Configuration Language (HCL)

Terraform is written in **Go language**, but Terraform configurations are written using **HCL (HashiCorp Configuration Language)**.

HCL is designed to be:

- Human readable
- Declarative
- Structured
- Machine parseable

It has syntax similar to many programming languages.

---

# HCL Syntax Structure

General structure:

```hcl
BLOCK_TYPE "LABEL1" "LABEL2" {
  ARGUMENT = VALUE
}
````

Example:

```hcl
resource "aws_instance" "web" {
  instance_type = "t3.micro"
}
```

| Component     | Meaning       |
| ------------- | ------------- |
| resource      | Block type    |
| aws_instance  | Resource type |
| web           | Resource name |
| instance_type | Argument      |
| t3.micro      | Value         |

---

# Core Components of Terraform Configuration

Terraform HCL consists of several important components:

* Resources
* Data Types
* Variables
* Locals
* Outputs

All these components work together to define infrastructure.

---

# Resource Address

Terraform identifies resources using the format:

```
RESOURCE_TYPE.NAME
```

Example:

```
aws_instance.web_server
```

---

# Arguments vs Attributes

## Arguments

Arguments are **values defined in the Terraform configuration**.

Example:

```hcl
instance_type = "t3.micro"
```

---

## Attributes

Attributes are **values generated by the provider after resource creation**.

Examples:

* public_ip
* id
* arn

Example reference:

```hcl
aws_instance.web_server.public_ip
```

---

# Terraform Data Types

Terraform supports multiple data types.

---

# String

```hcl
variable "instance_name" {
  type = string
}
```

Usage:

```hcl
tags = {
  Name = var.instance_name
}
```

---

# Number

```hcl
variable "instance_count" {
  type    = number
  default = 2
}
```

---

# Bool

```hcl
variable "enable_monitoring" {
  type    = bool
  default = true
}
```

---

# Set

Sets are **unordered collections**.

Terraform does **not allow accessing set elements by index directly**.

Example set:

```hcl
variable "example_set" {
  type    = set(string)
  default = ["foo", "bar"]
}
```

Convert set to list:

```hcl
locals {
  example_list = tolist(var.example_set)
}
```

Access elements:

```hcl
output "first_element" {
  value = local.example_list[0]
}

output "second_element" {
  value = local.example_list[1]
}
```

---

# List

Lists are **ordered collections of values**.

```hcl
variable "availability_zones" {
  type    = list(string)
  default = ["us-east-1a", "us-east-1b"]
}
```

Access element:

```
var.availability_zones[0]
```

---

# Map

Maps store **key-value pairs**.

```hcl
variable "tags" {
  type = map(string)

  default = {
    Environment = "dev"
    Project     = "terraform-demo"
  }
}
```

Usage:

```hcl
tags = var.tags
```

---

# Object

Objects allow **structured values**.

```hcl
variable "server_config" {
  type = object({
    instance_type = string
    volume_size   = number
  })
}
```

---

# Tuple

Tuples allow grouping **multiple values into a single value**, where each element has its own type.

```hcl
variable "example_tuple" {
  type = tuple([string, number, bool])
}
```

---

# Accessing Values

Elements of **list/tuple and map/object values** can be accessed using **square bracket notation**.

Example:

```
local.list[3]
```

Rules:

* List / Tuple → index must be a **number**
* Map / Object → index must be a **string**

Objects also allow **dot notation** if the attribute name is a valid identifier.

---

# Object Example

```hcl
locals {
  my_object = {
    instance_type = "t3.micro"
    volume_size   = 20
    monitoring    = true
  }
}
```

Access using dot notation:

```
local.my_object.instance_type
local.my_object.volume_size
```

Result:

```
t3.micro
20
```

---

# Object Access Using Bracket Notation

Objects can also be accessed using bracket notation.

```hcl
local.my_object["instance_type"]
```

Result:

```
t3.micro
```

---

# Why Bracket Notation Is Sometimes Preferred

If keys are **dynamic or user-defined**, dot notation may fail.

Example:

```hcl
locals {
  user_tags = {
    "project-name" = "terraform-course"
    "owner-team"   = "devops"
  }
}
```

Dot notation fails because the key contains a hyphen.

Correct approach:

```
local.user_tags["project-name"]
```

---

# Input Variables

Variables make infrastructure **dynamic and reusable**.

```hcl
variable "instance_type" {
  description = "EC2 instance type"
  type        = string
  default     = "t3.micro"
}
```

Usage:

```hcl
resource "aws_instance" "web" {
  instance_type = var.instance_type
}
```

---

# Variable Validation

Terraform variable validation ensures input values meet defined constraints.

Example:

```hcl
variable "environment" {
  type        = string
  description = "Deployment environment"

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}
```

---

# Variable Sources

Variables can come from:

* Default values
* terraform.tfvars
* CLI variables
* Environment variables

Example tfvars:

```
instance_type = "t3.small"
```

---

# Local Values (locals)

Locals are **temporary variables used within Terraform configuration**.

Example:

```hcl
locals {
  environment   = "dev"
  instance_name = "${local.environment}-server"
}
```

Usage:

```hcl
tags = {
  Name = local.instance_name
}
```

Benefits:

* Avoid repetition
* Compute derived values
* Improve readability

---

# Outputs

Outputs expose information **after infrastructure is created**.

Example:

```hcl
output "instance_ip" {
  value = aws_instance.web.public_ip
}
```

After running:

```
terraform apply
```

Example result:

```
instance_ip = 3.120.45.10
```

Outputs are useful for:

* Displaying infrastructure information
* Passing values to modules
* Integration with other tools

---

# Terraform Basic File Structure

Typical Terraform project structure:

```
project/
│
├── providers.tf
├── main.tf
├── variables.tf
├── terraform.tfvars
└── outputs.tf
```

### providers.tf

Defines which provider Terraform should use and authentication configuration.

---

### main.tf

Contains the main infrastructure resources and logic.

---

### variables.tf

Defines input variables to make the configuration flexible.

---

### terraform.tfvars

Used to assign values to variables.

---

### outputs.tf

Displays useful information after resources are created.
